Real CMS content for your Playwright tests. Each test cleans up after itself.

The package starts your Optimizely site, seeds the content your tests read, and gives each test pages of its own. They're created through the CMS and removed when the test ends. Fully typed, from your seed plan's step ids to opticli's error codes.

npm install -D @epinova/opticli

It runs the opticli CLI, of the same version or newer, so install that too. Works with CMS 12 and 13.

What happens on a test run

One global setup and a few fixtures. Your tests read content like any other page, and make their own when they need it.

  1. Setup starts the site

    With opticli serve, or it uses the site that's already running, including the one your IDE runs in IDE mode. It checks that opticli and the site's agent are at least the package's version, and points baseURL at the site. For a site that redirects to HTTPS, https: true serves it on https://localhost as well, and httpsPort keeps that port the same on every run. With profile, the site runs with a launch profile's database and settings.

  2. It seeds the content

    Your seed plan is applied on every run. The first run creates the content; later runs report it unchanged, or put back what a test changed. The plan has a fixed GUID namespace, so the content has the same GUIDs on every machine.

    On a database the CMS created from scratch, the plan also enables the languages and creates the sites. A page on another site opens on that site's own *.localhost host, and seed.sites names each site's address. See Build a test database from scratch.

  3. Each worker gets a sandbox

    A hidden page of its own below the seed content. Test pages go there, so parallel workers never touch each other's content.

  4. Each test makes its own pages

    cms.page() creates a page through the CMS, publishes it and returns its URL. Drafts, publishing, inline blocks and whole plans work the same way. Writes go through the CMS API, with versions, cache and events, so the page shows a change at once.

    After the test, what it made goes to the recycle bin, even when the test failed.

  5. Teardown

    Setup stops the site if it started it, and leaves one that was already running. The seed content stays for the next run.

Four files

A seed plan, a global setup, the config and your tests, in the order you'd write them. The plan is an ordinary opticli plan.

  1. e2e/seed.ts

    content every test can read

    import type { Plan } from '@epinova/opticli';export const seedPlan = {  guidNamespace: '0d6a8a5e-…',  operations: [    { op: 'create', id: 'root', parent: '/en/',      type: 'StandardPage', name: 'Test fixtures',      properties: { PageVisibleInMenu: false } },    { op: 'create', id: 'article', parent: '$root',      type: 'ArticlePage', name: 'Seeded article',      properties: { MainBody: '<p>Hello</p>' } },  ],} as const satisfies Plan;

    1. Any GUID, kept fixed: the seeded content gets the same GUIDs on every machine.

    2. Every step has an id. Later steps refer to it with a $, as $root below.

    3. Your tests open this page as seed.urls.article.

    4. as const keeps the ids exact, so the fixtures can type them.

  2. e2e/global-setup.ts

    start, seed, stop

    import { defineSetup } from '@epinova/opticli/playwright';import { seedPlan } from './seed.ts';export default defineSetup({  plan: seedPlan,  planDir: import.meta.dirname,});

    1. Starts the site with opticli serve, or uses the one already running.

    2. Applied on every run, putting back what a test changed.

    3. Where the plan's files are, for uploads and @file values.

  3. playwright.config.ts

    where test pages go

    import { defineConfig } from '@playwright/test';import type { OptiCliWorkerOptions }  from '@epinova/opticli/playwright';export default defineConfig<{}, OptiCliWorkerOptions>({  testDir: './e2e',  globalSetup: './e2e/global-setup.ts',  use: {    opticliSandbox: { parent: '$root', type: 'StandardPage',      properties: { PageVisibleInMenu: false } },  },});

    1. Each worker gets a hidden page of its own below $root. Test pages go there, so parallel workers never touch each other's content.

  4. e2e/fixtures.ts

    typed by your plan

    import { createTest } from '@epinova/opticli/playwright';import type { seedPlan } from './seed.ts';export const test = createTest<typeof seedPlan>();export { expect } from '@epinova/opticli/playwright';

    1. Types seed by your plan: seed.urls and seed.refs have a key for each step id.

  5. e2e/article.spec.ts

    seeded content, and content of the test's own

    import { expect, test } from './fixtures.ts';test('the seeded article', async ({ page, seed }) => {  await page.goto(seed.urls.article!);  await expect(page.getByText('Hello')).toBeVisible();});test('a draft shows once it is published', async ({ page, cms }) => {  const created = await cms.page('StandardPage', 'Draft test',    { MainBody: '<p>Published text</p>' });  const draft = await cms.set(created.ref,    { MainBody: '<p>Draft text</p>' });  await page.goto(created.url);  await expect(page.getByText('Draft text')).toHaveCount(0);  await cms.publish(draft.version!);  await page.reload();  await expect(page.getByText('Draft text')).toBeVisible();});

    1. A step id from the plan: a typo doesn't compile.

    2. Creates a page through the CMS in the worker's sandbox, publishes it and returns its URL.

    3. Saves a draft. Visitors still see the published version.

    4. Publishes it, through the CMS with its cache and events, so the page shows it at once.

    5. The test's page goes to the recycle bin here, even when the test failed.

A failed write throws OptiCliError with opticli's error code (not_found, validation, …) and its hint, such as the type's property names after a typo.

Limits

What to know before you build a suite on it.

  • Local and development databases

    opticli's own rules apply: the site runs against your local or chosen development database (opticli doctor shows which), and serve and every write are refused on a production database.

    never production
  • About a second per call

    Every call runs opticli once, and most of that second is .NET starting. Reading seeded content costs nothing per test; a page of a test's own costs two calls, create and delete. A plan makes a whole section in one call.

    ~1 s per write
  • The recycle bin fills up

    Test content is deleted the way the CMS deletes: to the recycle bin, never for good. On a local database that is usually fine; empty the recycle bin now and then.

    nothing purged

Get started

Playwright 1.40 or newer · opticli of the same version or newer · CMS 12 or 13

# opticli, pinned in the site's repository so CI gets the same
dotnet new tool-manifest
dotnet tool install OptiCli

# the package, in your Playwright project
npm install -D @epinova/opticli

# OPTICLI_PROJECT: the site, if setup can't find it
npx playwright test

The package runs opticli; it doesn't install it. It finds opticli in a tool manifest above your Playwright project, or on your PATH. A global dotnet tool install -g OptiCli works too.

The README has every option and fixture, and the Node.js API for scripts outside Playwright.
