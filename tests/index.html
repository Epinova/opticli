Real CMS content for your Playwright tests. Each test cleans up after itself.

@epinova/opticli starts your Optimizely site, seeds the content your tests read, and gives each test pages of its own. They're created through the CMS and removed when the test ends, unless a test keeps them. Fully typed, from your seed plan's step ids to opticli's error codes.

Install

npm install -D @epinova/opticli

It runs the opticli CLI, 0.28.0 or newer, so install that too. Works with CMS 12 and 13.

What happens on a test run

One global setup and a few fixtures. Your tests read content like any other page, and make their own when they need it.

  1. Setup starts the site

    With opticli serve, or it uses the site that's already running, including the one your IDE runs in IDE mode. It checks that opticli and the site's agent are at least the package's version, and points baseURL at the site.

  2. It seeds the content

    Your seed plan is applied on every run. The first run creates the content; later runs report it unchanged, or put back what a test changed. The plan has a fixed GUID namespace, so the content has the same GUIDs on every machine.

  3. Each worker gets a sandbox

    A hidden page of its own below the seed content. Test pages go there, so parallel workers never touch each other's content.

  4. Each test makes its own pages

    cms.page() creates a page through the CMS, publishes it and returns its URL. Drafts, publishing, inline blocks and whole plans work the same way. Writes go through the CMS API, with versions, cache and events, so the page shows a change at once.

    After the test, what it made goes to the recycle bin, even when the test failed.

  5. Teardown

    Setup stops the site if it started it, and leaves one that was already running. The seed content stays for the next run.

Four files

A seed plan, a global setup, the config and your tests. The plan is an ordinary opticli plan.

e2e/seed.tscontent every test can read
import type { Plan } from '@epinova/opticli';

export const seedPlan = {
  guidNamespace: '0d6a8a5e-…', // any GUID; keep it
  operations: [
    { op: 'create', id: 'root', parent: '/en/',
      type: 'StandardPage', name: 'Test fixtures',
      properties: { PageVisibleInMenu: false } },
    { op: 'create', id: 'article', parent: '$root',
      type: 'ArticlePage', name: 'Seeded article',
      properties: { MainBody: '<p>Hello</p>' } },
  ],
} as const satisfies Plan;
e2e/global-setup.tsstart, seed, stop
import { defineSetup } from '@epinova/opticli/playwright';
import { seedPlan } from './seed.ts';

export default defineSetup({
  plan: seedPlan,
  planDir: import.meta.dirname,
});
playwright.config.tswhere test pages go
import { defineConfig } from '@playwright/test';
import type { OptiCliWorkerOptions }
  from '@epinova/opticli/playwright';

export default defineConfig<{}, OptiCliWorkerOptions>({
  testDir: './e2e',
  globalSetup: './e2e/global-setup.ts',
  use: {
    // a hidden page per worker, below the seed's root
    opticliSandbox: { parent: '$root', type: 'StandardPage',
      properties: { PageVisibleInMenu: false } },
  },
});
e2e/fixtures.tstyped by your plan
import { createTest } from '@epinova/opticli/playwright';
import type { seedPlan } from './seed.ts';

export const test = createTest<typeof seedPlan>();
export { expect } from '@epinova/opticli/playwright';
e2e/article.spec.tsseeded content, and content of the test's own
import { expect, test } from './fixtures.ts';

test('the seeded article', async ({ page, seed }) => {
  await page.goto(seed.urls.article!);   // 'article' is a step id: a typo doesn't compile
  await expect(page.getByText('Hello')).toBeVisible();
});

test('a draft is not visible until it is published', async ({ page, cms }) => {
  const created = await cms.page('StandardPage', 'Draft test', { MainBody: '<p>Published text</p>' });
  const draft = await cms.set(created.ref, { MainBody: '<p>Draft text</p>' });

  await page.goto(created.url);
  await expect(page.getByText('Draft text')).toHaveCount(0);

  await cms.publish(draft.version!);
  await page.reload();
  await expect(page.getByText('Draft text')).toBeVisible();
});                                       // the page goes to the recycle bin here

A failed write throws OptiCliError with opticli's error code (not_found, validation, …) and its hint, such as the type's property names after a typo.

Limits

What to know before you build a suite on it.

  • Local and development databases

    opticli's own rules apply: the site runs against your local or chosen development database (opticli doctor shows which), and serve and every write are refused on a production database.

    never production
  • About a second per call

    Every call runs opticli once, and most of that second is .NET starting. Reading seeded content costs nothing per test; a page of a test's own costs two calls, create and delete. A plan makes a whole section in one call.

    ~1 s per write
  • The recycle bin fills up

    Test content is deleted the way the CMS deletes: to the recycle bin, never for good. On a local database that is usually fine; empty the recycle bin now and then.

    nothing purged
  • Not tried on CI yet

    A CI run needs what a local run needs: the .NET SDK, opticli, the site and a SQL Server with its database. That hasn't been tried in a pipeline yet, so there's no example pipeline.

    local runs
Get startedPlaywright 1.40 or newer · opticli 0.28.0 or newer · CMS 12 or 13
# opticli, pinned in the site's repository so CI gets the same
dotnet new tool-manifest
dotnet tool install OptiCli

# the package, in your Playwright project
npm install -D @epinova/opticli

# OPTICLI_PROJECT: the site, if setup can't find it
npx playwright test

The package runs opticli; it doesn't install it. It finds opticli in a tool manifest above your Playwright project, or on your PATH. A global dotnet tool install -g OptiCli works too.

The README has every option and fixture, and the Node.js API for scripts outside Playwright.
