Guides. One task, start to finish.

Each guide walks through one thing you'll want to do with opticli, with the commands, prompts and results along the way. For every flag and option, see the README.

For editors

Work on your site's content with your AI assistant: connect it, ask for changes, review the drafts.

  1. Connect your assistant to the CMSConnect Claude or another assistant to your Optimizely site, sign in with your own CMS account, and check that it works.
  2. Translate a page with your assistantHave your assistant translate a page into another language, review the translation as a draft, and publish it only when you say so.
  3. Fix image alt texts with your assistantHave your assistant look at your images, suggest alt texts or descriptions, and save them as drafts you review first.
  4. When someone else has changes on the pageUnderstand why your assistant stops before publishing a colleague's unpublished changes, decide what goes live, and send pages for review where an approval sequence applies.

For developers

Use the opticli CLI, on your own or with your coding agent, on a site you develop.

  1. Work on a restored production databasePoint opticli at a restored copy of production, make its sites answer on localhost, get a local login and keep its scheduled jobs from running.
  2. Find content and the code behind itGo from a URL or a name to the content item, its C# class and Razor view, and every page that uses it.
  3. Seed CMS content for Playwright testsUse the @epinova/opticli npm package to start the site, seed the content your Playwright tests read, and give each test pages of its own that are cleaned up afterwards.
  4. Pull content from staging into your local databaseRegister a staging or test database by name, bring its content into your local database with sync pull, and keep it current without another restore.
  5. Build a test database from scratchStart from an empty database, and let one seed plan add the languages, the content and the sites, so end-to-end tests run on a database that code builds the same way every time.

For the MCP module

Install the editors' MCP server in a site, give it tools of your own and get it ready for production.

  1. Install the MCP module in your siteAdd the opticli MCP module to a CMS 12 or CMS 13 site, decide what assistants may do, and connect a first assistant to check that it works.
  2. Write your first site-specific toolAdd a read tool and a write tool of your own to the MCP module, so editors' assistants can find Alloy product pages without a teaser and fill them in as drafts.
  3. Take the MCP module to productionConfigure the MCP module for a shared or production environment, from which assistants may connect and how the site is reached to error pages, uploads, the audit log and preview links.
