Let AI and tests work on real Optimizely content.

For coding agents, for editors' AI assistants and for Playwright tests. Whichever way in, every change goes through your site's own CMS.

For coding agents

The CLI

Your coding agent finds pages, blocks and the code behind them, and changes content as drafts you review. Production stays read-only.

opticli set 7 TeaserText='Plan, track and report with the whole team'

Alloy Track saved as a draft, not published

dotnet tool install -g OptiCli

For editors

The MCP server

Editors ask the AI assistant they already use. It signs in as them, works with their access rights and saves drafts.

“The Alloy Track teaser should mention reporting.”

Saved as a draft in your name, with a preview link

dotnet add package OptiCli.Mcp

A developer adds it to the site once. The MCP server

For tests

The npm package

Playwright tests get seeded content and pages of their own, made through the CMS and cleared away after each test.

visitors see a draft only once it is published

the seeded article shows its body and teaser

npm install -D @epinova/opticli

The test package

All three save through your site's own CMSvalidatedversionedwith access rightswith events and caches as when an editor saves

Nothing writes straight to the database.

  1. The CLI writes through a small agent loaded into your running site, with no changes to your solution.

  2. The MCP server lives in the site and acts as the signed-in editor, with drafts by default and publishing off until the site turns it on.

  3. The test package runs the CLI, so every page a test makes goes through the CMS too.
