❯opticli

A command-line tool for the content in your Optimizely CMS 12 site. Look up pages and blocks, trace them to the code that renders them, and change them through the CMS API, from your terminal or through your coding agent.

What it's for

  • Answer content questions without SQL

    No more hand-written queries against tblContent. Items come back with every property decoded, including ContentAreas, local blocks, links and rich text. Reads go straight to the database, so the site doesn't need to be running.

    opticli get 123 --fields MainContentArea

  • Go from content to code

    See the C# class for a content type, the source line of each property and the Razor views, plus which ContentAreas accept it according to [AllowedTypes].

    opticli type TeaserBlock

  • Know what a change will affect

    Find every page and block that references an item, through nested blocks all the way up to pages. You can also resolve a URL to content, or list the unpublished drafts.

    opticli where-used 456 --pages

  • Change content through the CMS API

    Writes go through IContentRepository inside your running site, so validation, versioning, events and caches all work. Changes are saved as drafts unless you publish, and every write command takes --dry-run.

    opticli set 123 Heading="New title" --dry-run

  • Nothing to add to your solution

    serve starts your existing build with a small agent injected at startup, through a .NET startup hook and a hosting startup. Your site's code and config stay as they are.

    opticli serve

  • Built for coding agents

    Piped output is compact JSON. Every item has a ref you can pass to the next command, and errors come with a code and a hint. A Claude Code skill tells the agent when to use opticli and how to use it safely.

    opticli skill install

How it works

Readsopticli── fixed read-only SQL ─▶CMS database
Writesopticli── 127.0.0.1 + token ─▶agent in your running site── IContentRepository ─▶CMS database
  • Your local database by defaultopticli reads the connection string from the site's Development config. To use a remote database you have to choose it explicitly, and every response then carries a warning.
  • Read-only readsReads use fixed queries. opticli sql accepts a single SELECT against the site's own database and runs it in a transaction that is rolled back.
  • Nothing permanent by accidentChanges are saved as drafts by the user opticli. Publishing needs --publish, and delete only moves content to the recycle bin.

Get started

You need the .NET 8 SDK or newer. Run opticli from anywhere inside a CMS 12 site's repository.

# build and install as a global tool
git clone https://github.com/epinova/opticli.git && cd opticli
dotnet pack src/OptiCli -c Release -o artifacts
dotnet tool install -g OptiCli --add-source ./artifacts

# then, in your site's repository
opticli doctor                          # what it found: project, database, content types
opticli resolve https://example.com/en/about/
opticli skill install                   # teach Claude Code to use it
