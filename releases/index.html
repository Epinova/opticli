Releases

What changed in each release of the CLI, the MCP server and the npm package. Every release is on nuget.org and npm. After updating the CLI, run opticli skill install again to update the skill.

  1. 0.36.024 November 2026
    • Optimizely Commerce: on a site with Commerce 14 (CMS 12) or 15 (CMS 13), serve loads a Commerce agent beside the site agent, so an E2E suite can seed a catalog from code. Catalogs, nodes, products and variants are content for create, set and plans, with code: and catalog: refs and product images. Prices, warehouses, stock, markets and relations get opticli commerce … commands and plan steps, all with dry runs and unchanged on a re-run. A site without Commerce runs as before, and the MCP module is unchanged. See the guide Seed a Commerce catalog for Playwright tests.
    • Reads through the site: commerce get|children|tree, prices, stock, markets and relations, and resolve takes a catalog URL back to its ref.
    • Fixed: opticli sql with a recursive CTE cut by --limit reported an internal error. It now gives SQL Server's own error, and past the recursion limit the hint names OPTION (MAXRECURSION n).
  2. 0.35.223 November 2026
    • Fixes from a review of every write and the MCP module: unpublish no longer publishes a page's never-published blocks along with it, a block whose draft holds a colleague's changes goes live with a page only when named, and a block published along has a passed stop date cleared.
    • Plans don't stop half-way: a later step's publishAt and requestApproval, one content in two projects, and a publish after an upload's new file are now checked in the dry run. A link out of the plan's folder is refused, also in a sealed run.
    • For editors' assistants: a save into a project needs Edit even with nothing to change, renaming a folder with content below it needs publishing allowed, and blocks or content an editor can't read are named nowhere. A site tool with [Authorize] stops the site at startup instead of being open to every editor.
    • New: serve warns when no site answers on its address, and says which port or command makes one answer.
  3. 0.35.119 November 2026
    • Fixed: opticli env --connection-name without --include-connection now tells the site agent which connection string the site uses. It checked EPiServerDB instead, so a site without that string wouldn't start.
    • The reference moved: the README is now a quickstart, and the reference is in docs/reference/, one page per area, checked against the code on the way.
  4. 0.35.019 November 2026
    • New blocks follow the site's edit UI: where the site has UIOptions.InlineBlocksInContentAreaEnabled off (Optimizely's default on CMS 12), a new block in a ContentArea is now a shared block in the page's “For this page” folder, as an editor would make it, instead of an inline block the site may not render. Inline blocks a page already has stay inline, and writing an area again updates its blocks instead of making new ones. The result's sharedBlocks gives each block's ref.
    • Publishing takes only what you mean: a publish takes along the page's never-published blocks, but a live block's newer draft, or a colleague's draft, goes live only when you name it (--with-block, blocks). Replacing a colleague's block draft needs --include-draft. publish --dry-run and publish_content's new dryRun show what goes live.
    • For editors: a new guide, Add blocks to a page.
  5. 0.34.218 November 2026
    • Fixed in the Claude Desktop extension: after a sign-in that wasn't finished, every later sign-in page said “Unknown app” and Claude Desktop gave up. The extension now drops a saved registration that never signed in and registers again.
  6. 0.34.117 November 2026
    • Fixed on Windows: when the npm package, a script or an agent read opticli's output, characters outside ASCII (æøå in a content name) came out wrong, and a plan piped to apply - was read the same way. Redirected input and output are UTF-8 now.
  7. 0.34.017 November 2026
    • A typed method for every command: the npm package's client is generated from opticli's own description of its commands, with the CLI's shape and each command's JSON as the return type: cli.languages(), cli.projects('Spring campaign'), cli.whereUsed('123', { pages: true }). OptiCliSync has the same methods, blocking, for a playwright.config that makes a project per enabled language. The API changes where 0.33's no longer fit; see the changelog. See the guide Read the site from Node.js scripts and playwright.config.
    • Projects in tests: cms.page() and cms.set() take inProject and ready, and a project a test makes is deleted after the test.
    • On the command line: a value that starts with @ is plain text (opticli search @alloy), and plans that replace a file they upload work.
    • For editors' assistants: get_content_type gives the block types an editor descriptor allows, and saves follow them, as the edit UI does.
  8. 0.33.017 November 2026
    • Changes collected in a project: drafts can go into the CMS's projects, so editors review many related changes together and publish them in one go. Your assistant can create a project, put its drafts in it, mark them Ready to publish and, where the site allows it, publish or schedule the project. Only items marked ready go live; the rest stay drafts. See the guide Collect changes in a project and publish them together.
    • On the command line: --in-project and --ready on the writes, "project" in plans, and opticli projects create, ready and publish. See the guide Hand a batch of changes to editors as a project.
  9. 0.32.012 November 2026
    • Sites with assets of their own: a site that opticli sites add or a plan's site step creates now gets an assets folder of its own, at /siteassets/, as admin mode makes it, so add-ons that keep data in a site's assets folder find one. A seed plan can upload straight into it by its URL; --site-assets global keeps a site on the shared folder. See the guide Build a test database from scratch.
    • Fixes in plans that create sites: a step on the new site's host waits for the site instead of failing the dry run, and a page that links elsewhere keeps that link as its URL on the first run too.
  10. 0.31.111 November 2026
    • What the site's own code changed: when the site's code changes a value during a save, the result shows what was stored, not what was asked for, and opticli warns about it.
    • External links: a page whose shortcut is an external link has that link as its URL again.
